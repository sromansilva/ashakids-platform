## 03. APIs funcionando: identidad y participantes

Cada consulta exige sesión válida y roles PADRE/TERAPEUTA por perfil vinculado al usuario. ADMIN solo no concede acceso privado. Contactos surgen de pacientes activos, tratamiento ACTIVO y ambos usuarios habilitados, sin directorio general ni nombres ficticios.

| Método y ruta | Estado | Regla / evidencia |
| --- | --- | --- |
| POST /auth/login | 200 | Cinco cuentas sintéticas; cookies independientes |
| GET /conversaciones, anónimo | 401 | Sin acceso a listas privadas |
| GET /conversaciones, ADMIN | 403 | Rol administrativo sin permiso de chat |
| GET /conversaciones/contactos | 200 | Familia y terapeuta asignados ven la misma pareja; otros dos ven lista vacía |
| POST /conversaciones | 200 | Dos aperturas simultáneas devuelven conversación1, sin dos chats nuevos |
| POST /conversaciones, pareja ajena | 403 | Otro padre/profesional no inicia el chat |
| GET /conversaciones/{id} o /mensajes | 404 | Recursos ajenos/no existentes no se revelan |
| GET /conversaciones/{id}/mensajes, ADMIN | 403 | Rechazo explícito de rol no participante |

Contactos se pagina mediante limit/offset y X-Total-Count; React reúne las páginas con el cliente existente. La lista de conversaciones usa ID descendente y next_before_id; no ordena por presencia ni simula disponibilidad.

Historial: el participante conserva lectura cuando termina la asignación. Estado cerrado o fecha_archivado impide envío con409; falta de asignación activa impide envío con403. Estas transiciones se comprobaron en unidades con dependencias simuladas: no se cambió un tratamiento o paciente para reproducirlas en SQL.

Las operaciones anteriores no constituyen un nuevo ensayo de CRUD de pacientes/usuarios/tratamientos. Esos recorridos y permisos permanecen como evidencia de cortes anteriores, sin sumar sus cifras a este informe.

## 06. Seguridad y riesgos priorizados

| Prioridad | Hallazgo y comprobación | Acción / límite |
| --- | --- | --- |
| Alta | Recurso ajeno404; ADMIN403; entrada extra422 | Mantener permisos del servidor; claves de caché por identidad no conceden autorización |
| Alta | No comparación compartida nueva; incidencia01 abierta | Revisar incidencia y entorno antes de declarar estabilidad/desplegar |
| Media | Respuesta perdida puede ocultar mensaje ya guardado | POST sin clave idempotente; actualizar antes de reenviar, no auto retry |
| Media | Sin UNIQUE pareja; no garantía entre escritores externos | Bloqueo válido para esta API; medir/revisar migración si se amplían escritores |
| Media | Revisión visual final y segundo clon pendientes | No certificar dispositivos o reproducción por terceros sin ejecutar |
| Baja | No carga, retención, búsqueda ni índice cursor compuesto nuevo | Medir volumen y requisitos antes de ampliar arquitectura |

React muestra markup como texto: la prueba de componente con cadena HTML no genera un elemento img. La corrida SQL conserva texto con etiquetas y emoji; no prueba ejecutarlos en un navegador. NUL se rechaza antes de PostgreSQL. Las consultas usan SQLAlchemy parametrizado; el contenido no se concatena como SQL.

Un chat archivado o sin asignación conserva historial a sus participantes. No se permite restaurarlo desde este módulo. Revocar la relación desde un escritor externo simultáneo no es una garantía atómica del bloqueo de conversación: el esquema y las demás escrituras no cambian en este corte.

Se reutiliza cookie HttpOnly, validación de sesión/origen y apiClient existentes. Esta auditoría no vuelve a certificar atributos de cookie HTTPS/CORS en un dominio desplegado. La revisión dirigida de secretos comprueba textos cambiados y PDF extraído contra valores sensibles locales y patrón JWT, sin imprimirlos; no es detección exhaustiva ni pentest.

No se han escrito datos de pacientes reales ni credenciales en las evidencias. Fixtures sintéticas y filas de mensajes se conservan para una demostración repetible.
