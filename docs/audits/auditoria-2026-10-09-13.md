## 02. Arquitectura y cambios realizados

React -> cliente HTTP/JSON -> FastAPI -> servicios/Pydantic -> SQLAlchemy/asyncpg -> PostgreSQL en Supabase. Se conservan Argon2id, sesiones opacas hasheadas, cookie HttpOnly, roles PADRE/TERAPEUTA/ADMIN y autorización por recurso. Sin Supabase Auth, acceso directo desde React, módulos nuevos ni rediseño frontend.

TLS remoto usa CERT_REQUIRED y check_hostname=True con CA privada configurada. La conexión válida negoció TLS 1.3/TLS_AES_256_GCM_SHA384; una trust store vacía fue rechazada. El primer intento falló con código 92 porque la CA 2021 carece de keyUsage. DB_SSL_LEGACY_CA permite explícitamente ese formato y está desactivada por defecto; conserva cadena, vigencia y nombre. Retirar la excepción cuando el proveedor entregue una cadena compatible. Referencia: https://docs.python.org/3.13/library/ssl.html .

Producción exige entorno y orígenes HTTPS explícitos; rechaza escrituras recibidas por HTTP. Login limita por IP e IP/código, con ventana fija y memoria acotada. Las rechazadas no prolongan el bloqueo ni bloquean globalmente una cuenta desde otra IP. Estado local a un proceso: reinicios lo borran y no coordina réplicas. WEB_CONCURRENCY es una guarda de configuración, no detecta workers fijados por CLI. Decisión y límites: ADR 0009 y operations/BACKEND_SECURITY_CONFIGURATION.md.

Administración se divide en lectura, creación, estado, eliminación y auditoría; admin_service conserva imports públicos y edición. La serialización de pacientes se separa de operaciones SQL. Comparación AST: 14 funciones administrativas y 13 de pacientes mantienen cuerpos idénticos. Todos los Python modificados tienen como máximo 500 líneas; máximo observado 499. No cambios generales de carpetas ni dependencias runtime.

Contraseñas nuevas: 12-128 caracteres en usuarios y administración; ese mínimo no se aplica al login. Escritura de sexo admite M/F/OTRO y palabras, normaliza a Masculino/Femenino/Otro; lectura preserva valores existentes sin migrar filas. Nombres vacíos y nacimiento futuro se rechazan en ambas familias. No se bloquea edición de datos antiguos por edad actual. Null explícito en PATCH hijos se rechaza; campos omitidos se conservan.

FOR UPDATE refresca el estado ORM con populate_existing. Commit previo al éxito y rollback se conservan; fallo de rollback no sustituye el error inicial. Deadlock/serialización e integridad devuelven 409; conexión/timeouts, 503. Sin reintentos automáticos, migraciones ni restricciones nuevas.

Modelo físico leído: 26 tablas, 178 columnas, 92 restricciones (26 PK, 34 FK, 13 UNIQUE, 19 CHECK), 71 índices y 26 secuencias. 19 tablas ORM: 0 diferencias de columnas/tipos/nulabilidad/longitud/precisión inspeccionadas. Relaciones: usuario -> roles/perfiles/sesiones auth; tutor -> paciente -> expediente -> tratamiento; profesional -> tratamiento/cita; reserva -> sesión -> reporte; tutor/profesional -> conversación -> mensajes. RLS habilitada, 0 políticas públicas; el rol actual omite RLS. Metadatos no certifican todos los defaults, reglas ni autorización de cada fila.
